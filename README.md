## 只做这些事

当前测试版跟随系统深色模式，不加应用内手动切换。

以下基础功能沿用 alpha.7 / alpha.8，包含在 alpha.12 测试版中。作者此前确认两项提醒选择修复与阶段 G 当天庆祝通过；通知送达、重启恢复与小组件后台行为不据此扩大为已验收，相关验收清单仍保留。

- 直接创建日子：名称、日期、分类、备注、置顶。
- 表单内展开圆角日期选择器：公历与农历同看、节日 / 节气提示、输入年份快速选月、选择今天；浏览不改值，点选日期才确认。
- 过去的日子显示「已经 X 天」，未来显示「还有 X 天」，当天显示「就是今天」。不重复的记录按实际经过天数计算，起始当天是 0 天。
- 公历 / 农历年度重复：生日、周年纪念日显示下一次到来的倒计时。
- 可直接按农历选日期；每年重复的生日和纪念日显示岁数 / 周年。
- 单页浏览、分类筛选、关键词搜索、临近优先 / 日期排序。
- 左上角打开轻量月历：公历 / 农历、传统节日与节气、干支生肖、日子标记；点选日期查看、新增或编辑记录。农历信息沿用旧版计算库，不表示官方放假 / 调休安排。
- 本地 IndexedDB 保存；JSON 导出、预览并合并导入；同源多窗口刷新。
- 显式迁移旧版人物生日、年度纪念日；不修改旧版数据库。
- Web / PWA；保留 Android Capacitor 工程和原生文件保存器。
- 本地提醒：可选当天 / 提前 1、3、7 天，每条日子可设置分钟级时间，未单独设置时继承全局时间；Android 12+ 的精确提醒权限未获准时继续非精确排程并显示说明。仅 Android 应用内提供，Web/PWA 无提醒界面或通知，不使用服务端。
- 加入系统日历：Android 详情页打开系统事件编辑器，全天、公历年度重复或单次事件；农历年度重复只加入下一次，需每年重新加入。不申请 READ/WRITE_CALENDAR，由日历 app 使用自己的默认提醒并由用户确认保存。
- Android 桌面小组件（2×2）：显示与首页相同的那一个日子，每天自动更新；不含农历实时换算，打开 app 后即刷新。仅 Android，不做 iOS 或 Web 小组件。

alpha.4：原生端在置顶、保存、删除等操作上提供轻微震动反馈（需要震动权限）。Web / PWA 不加载原生触觉插件。

alpha.4 还加入日子详情（先查看，再编辑；不提供图片分享），共用的农历月历与年月跳转、横滑切月。日历浏览月份与 agenda 选中日期独立；移动首页仅保留日期行、紧凑概览及吸顶工具栏，桌面保留原布局。

不再包含：人物档案、地点库、回忆与照片管理、复杂安排与待办、统计、账号、Notion、二维码分享、内置更新器。

**不提供云同步或里程碑。** 这不是在后台继续运行旧系统、只把入口藏起来：旧业务已经移出活动源码和构建依赖。

全局提醒时间在「数据与备份」的内联面板设置，支持任意 `HH:mm`，默认 09:00；它只保存在本机，不随 JSON 备份迁移。每条记录的可选 `reminderTime` 随备份导入导出；旧备份缺省时继承当前设备的全局时间。编辑器可点「用全局时间」恢复继承。拒绝通知权限不丢失提醒选项，到系统设置授权后再打开应用会补排。精确提醒权限检查不弹窗，拒绝时排非精确；只有编辑器里的「去开启」会打开系统设置，回到前台重新检查并重排。每年重复（含农历）只排下一次，最多保留最早 64 条通知；不承诺长期不开应用时无限逐年续排。分钟级指设置和计划时间的粒度；休眠／省电、未允许通知、非精确批处理等仍可能延迟，**不保证一分钟内或准点送达**。

小组件使用应用最近一次写入的首页快照：在原生端按当前本地日期更新天数，置顶／修改／删除后以及打开／恢复应用时刷新快照。记录排序与公历／农历年度重复的下一次日期由应用计算，不承诺长期不开应用时自动切换推荐记录或逐年续算。每天 00:05 的非精确刷新与宿主 30 分钟更新周期可能被系统延后，**不是准点或最长 30 分钟的保证**；点击可进入该记录详情，空列表提示「记下第一个日子」。

## 旧数据怎么处理

1. 在旧版先导出完整 JSON 备份（含照片的原备份也请保留）。
2. 新版右上角 → **数据与备份** → **从本机旧版迁移**。
3. 查看识别数量，再确认合并。只读取 `LifeLogDatabase.people`；旧版 localStorage 也有只读兼容路径。
4. 不同设备、不同域名或开发端口无法直接读取旧存储，请选择 **导入备份**。
5. 同 ID 的记录跳过、不覆盖现有修改；无效旧日期会报告跳过数量。非法新版备份整份拒绝，不部分写入。

新版使用独立的 `LifeLogDays` 数据库。原人物、地点、回忆、照片、安排不会被删除，但**新版不能浏览或编辑这些旧内容**。新版导出仅包含日子，不能代替旧版的完整备份。再次手动导入旧备份会重新添加已在新版删除的旧记录。

### 日期约定

- 按本地日历日期计算天数，不使用经过小时数，避免夏令时误差。
- 公历 2 月 29 日在非闰年按 2 月 28 日纪念。
- 农历输入仍选择原始**公历日期**，表单显示转换结果；之后按对应农历日期重复。无闰月的年份回退到同名普通月，农历三十在小月回退为廿九。
- 支持录入 1901–2099 年的日期；数据限制为 10,000 条，单个 JSON 文件最大 128 MB。
- 年度重复的起始日期在未来时，不会在首次日期之前生成周年。

### 本机测试 APK

Android 构建入口会将校验后的独立测试包放在 `react-app/.artifacts/`（不提交 Git），并生成同名 `.apk.json` 校验报告。测试包使用 debug 签名，不能作为正式发布包。

在这台机器的新终端里，先执行 `source "$HOME/.local/share/lifelog-android/env.sh"` 加载已安装的工具链，再运行 Android 构建命令。其他机器需自行配置环境。
