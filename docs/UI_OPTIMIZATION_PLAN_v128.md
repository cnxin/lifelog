# LifeLog 界面优化方案（基于 0.1.0-test.128）

> **现行主方案**：[`OPTIMIZATION_MASTER_PLAN.md`](./OPTIMIZATION_MASTER_PLAN.md)
> 状态：诊断归档（129–132 已吸收部分项；剩余并入主方案 Phase B）
> 日期：2026-07-12  
> 基线：`0.1.0-test.128` 已完成流体手感  
> 设计定位：柔和、私人、温暖、轻量精致（见 `react-app/.impeccable.md`）  
> 原则：**先减噪与统一，再加视觉；不扩云同步/协作类大功能**

---

## 0. 一句话结论

128 解决了「手感像原生」；下一阶段应解决 **「看起来像一本贴身记录本，而不是功能仪表盘」**。  
最大收益不在新功能，而在：**首页信息架构、空状态与首次路径、列表视觉层次、顶栏搜索入口、主题/暗色一致性**。

---

## 1. 现状诊断（对照代码）

### 1.1 已经不错的地方

| 点 | 证据 |
|----|------|
| 流体交互主路径 | Sheet / PhotoViewer / FAB / pressable（128） |
| 主题 token 基础 | `01-tokens.css` 四套风格 + 系统 dark 变量 |
| 列表能力完整 | 搜索、筛选、紧凑/详细、批量管理 |
| 首页有自适应 | `useHomeLayout` + 偏好记忆 |
| 移动端安全区 | bottom-nav 使用 `safe-area-inset-bottom` |

### 1.2 当前主要问题

#### A. 首页「记录本」感不足，偏仪表盘

`Home.tsx` 同时堆叠：

1. 大标题「今天的 LifeLog」  
2. 四格统计卡（人物/地点/回忆/本月）  
3. 今日待办队列  
4. 智能建议  
5. 历年今日  
6. 本月安排  
7. 补全任务  
8. 最近看看（人物/地点/记录）

**结果：** 有数据的老用户首屏很满；无数据的新用户看到数字全是 0 的统计卡，缺少「写下第一句」的焦点。

#### B. 标题语义重复

- 全局 `Header` 已有问候标题/副标题  
- 首页内部又有 `h1`「今天的 LifeLog」  
→ 同一屏两套主标题，层级打架。

#### C. 空状态与加载态薄弱

- 列表/详情大量使用 `GlassCard className="empty"` 纯文字  
- 未见统一 `EmptyState` / skeleton 组件体系  
- 首次打开本地数据加载只有简单 spinner，缺骨架过渡

#### D. 搜索入口权重偏低

- 搜索只是 Header 小图标  
- 产品已有全局搜索（Cmd/Ctrl+K），但视觉上不像「主要找东西入口」  
- 数据变多后，用户仍会先在各列表页筛，而不是全局搜

#### E. 卡片视觉同质化

- 人物 / 地点 / 回忆大量依赖同一套 glass-card + 紫底图标徽章  
- 回忆列表缺少缩略图预览（有照片的条目也只显示计数）  
- 计划 vs 已发生 主要靠小 pill，扫视成本高

#### F. 顶栏/底栏材质未完全「浮层化」

- bottom-nav 已有玻璃感，但 Header 与内容滚动关系不够「内容从下方穿过」  
- 半透明叠半透明时，部分主题下文字对比可能偏弱

#### G. 暗色与主题一致性有债

- tokens 有 `prefers-color-scheme: dark`，但 4 套主题风格与系统 dark 叠加规则不直观  
- cream/mint/mist 在暗色下可能只是「换底」，品牌色层次未单独校准

#### H. 页面工程体积影响 UI 迭代速度

- `Home.tsx` ~1275 行、`07-pages.css` 巨石  
- 界面优化容易牵一发全身，建议与视觉改造并行做「可改性」拆分

## 2. 优化目标与非目标

### 2.1 目标

1. **3 秒内看懂今天该干什么**（待办/回忆/记录）  
2. **0 数据时仍有温暖引导**，不是空白统计  
3. **列表扫读更快**：照片、类型、时间一眼可分  
4. **找东西更快**：搜索像一级能力  
5. **视觉更克制**：少一层装饰，多一层呼吸感  

### 2.2 非目标（本轮不做）

- 云同步 / 家庭协作 / 新社交分享  
- 重做整套插画品牌  
- 大改信息架构到 5 Tab 以上  
- 引入重型 UI 库  

### 2.3 成功指标（可手测）

| 指标 | 目标 |
|------|------|
| 首页首屏模块数（有待办时） | ≤ 3 个展开主区块 |
| 新用户 0 数据首屏 CTA | 1 个主按钮直达「记一件事」 |
| 从打开 App 到开始输入 | ≤ 2 次点击 |
| 回忆列表含图条目 | 可见缩略图（compact 可隐藏） |
| 空列表 | 统一插画/图标 + 一句说明 + 主操作 |
| 暗色正文对比 | 主要文字清晰可读（人工走查 4 主题） |

## 4. P0 详细方案

### 4.1 首页信息架构：从仪表盘回到「今天」

#### 目标结构（有数据老用户）

```
[Header 问候]
[可选：今日待办 折叠摘要 1 行]     ← 仅有待办时
[主焦点：历年今日 或 本月下一件]   ← 二选一优先展示
[快捷记录条 / 一键记事]           ← 常驻轻量
[最近 3 条] 折叠「更多」
```

#### 目标结构（0–10 条新用户）

```
[温暖欢迎句]
[主 CTA：写下今天第一件事]
[次 CTA：先记一个人 / 先记一个地方]
[可选：3 个补全提示中的最多 1 条]
```

#### 具体改动

| 改动 | 说明 |
|------|------|
| 去掉首页内层大 `h1` 或降为 eyebrow | 避免与 Header 双标题 |
| 统计四宫格默认折叠/下沉 | 移到「最近看看」或账号/统计页；首页只保留「本月 N 条」一句文案即可 |
| 今日待办默认摘要一行 | 已有折叠，强化默认收起策略：>2 条才展开 |
| 智能建议与待办互斥已有 | 保持；文案更短、更像便签 |
| 补全任务仅新用户且最多 2 条 | 老用户隐藏「补高德/补生日」类噪音 |
| 增加「快捷记录条」 | 首页中部假输入框：「今天发生了什么…」点开 quick sheet |

#### 文件

- `pages/Home/Home.tsx`（结构）  
- `hooks/useHomeLayout.ts`（默认展开规则）  
- `styles/07-pages.css` 中 home 段  

#### 验收

- 有待办：首屏不需要滚动就能点到第一条待办或记事  
- 无数据：首屏只有欢迎 + 主 CTA，没有四个 0  
- 老用户：默认看不到大片补全任务  

---

### 4.2 统一空状态与加载骨架

#### 组件

```
components/EmptyState.tsx
  props: icon, title, description, primaryAction?, secondaryAction?

components/ListSkeleton.tsx
  props: rows?: number, variant?: 'card' | 'detail'
```

#### 覆盖页面

| 场景 | 文案方向 |
|------|----------|
| 回忆为空 | 「还没有记录。先写今天的一件小事。」→ 记一件事 |
| 人物为空 | 「先留下一个重要的人。」→ 记一个人 |
| 地点为空 | 「想再去的地方，先记下来。」→ 记一个地方 |
| 搜索无结果 | 「没有匹配。试试人名、地点或日期。」 |
| 筛选无结果 | 「当前筛选太窄」+ 清除筛选 |
| 详情找不到 | 返回列表 + 去首页 |

#### 加载

- App 首次 `isLoading`：用 3–4 条卡片骨架替代纯 spinner  
- 列表切换筛选：可选顶部细进度，避免整页闪白  

#### 验收

- 任意主列表空态都有图标 + 一句人话 + 可点主按钮  
- 冷启动不再只有居中「正在加载本地数据」  

---

### 4.3 搜索入口升级

#### UI

1. **首页 Header 下增加搜索 pill（可选仅首页）**  
   `搜索人物、地点、回忆` — 点击打开现有 `GlobalSearchPanel`  
2. 或 **Header 搜索图标加大 + 长标签「搜索」**（小屏只图标）  
3. 全局搜索空态强化：最近搜索 / 推荐语法（`@人名`、日期）— 若已有则提高视觉权重  

#### 不改

- 不重写搜索算法  
- 不新增桌面-only 依赖  

#### 文件

- `components/Header.tsx`  
- `components/AppLayout.tsx`（可传 `showSearchPill`）  
- `components/GlobalSearchPanel.tsx`  

#### 验收

- 首页 1 次点击进入搜索  
- 新用户也能发现搜索（不只是快捷键）

## 5. P1 详细方案

### 5.1 列表卡片：让「类型」和「照片」先说话

#### 回忆卡

| 现在 | 建议 |
|------|------|
| 统一心形徽章 | 计划用日历色块，回忆用心形/照片色 |
| 有图只显示数字 | **详细模式左侧 48–56px 缩略图**；紧凑模式保留计数 |
| 内容/标签易挤 | 详细：标题 + 一行 meta + 可选一行正文截断；标签最多 2 个 + N |

#### 人物卡

- 头像用姓名色相（已有 initials）保持  
- 关系温度/天数用更短 meta：`朋友 · 12 天未见`  
- 批量模式选择框与主点击区分离（避免误触）  

#### 地点卡

- 分类用轻色 chip，而不是只靠文字  
- 常去地点显示 `去过 N 次` 优先于地址全长  

#### 文件

- `MemoryCard.tsx` + Photo 缩略加载工具（复用现有 blob/thumb 逻辑）  
- People/Places 列表行组件（若内联则抽 `PersonRow`/`PlaceRow`）  

#### 风险

- 缩略图 object URL 泄漏 → 必须复用已有生命周期管理  

---

### 5.2 顶栏 / 底栏：浮层材质统一

#### 建议

```
Header:
  position sticky
  background: color-mix(card-solid 72%, transparent)
  backdrop-filter: blur(16px) saturate(160%)
  底边：渐隐 mask 或极淡 line，不用粗分割

BottomNav:
  保持悬浮胶囊
  激活态：点 + 轻微 scale（已有 pressable）
  页面内容 padding-bottom 与 FAB 避让统一 token
```

#### reduced-transparency

- 已有 `09-motion.css` 规则，扩展到 header  

#### 验收

- 滚动时内容从顶栏下穿过，文字仍可读  
- 系统降低透明度时顶栏变实色  

---

### 5.3 主题与暗色对比校准

#### 工作项

1. 为 4 主题各补一套 **显式 dark tokens**（不要只靠通用 dark 覆盖 primary）  
2. 统一检查：  
   - `--text-sub` 在 soft 背景上的对比  
   - 计划 pill / danger / success  
   - glass-card 边框在 dark 下是否「糊成一片」  
3. 设置页主题预览：四宫格实时小预览（可选）  

#### 验收

- cream/mint/mist/classic × light/dark 共 8 态走查通过

## 6. P2 详细方案

### 6.1 详情页阅读体验

- 回忆详情：正文字号/行高按「阅读」优化（`line-height ~1.65`，段间距）  
- 关联人物/地点改为文内 chip 流，减少再套一层大卡片  
- 折叠区默认策略：无照片时不展示空照片块  
- 分享/编辑主操作固定在内容底或顶栏，避免滚丢  

### 6.2 页面切换与微交互

- 路由切换：短 cross-fade（reduced-motion 关闭）  
- 列表项进入：可选极轻 stagger（仅首屏 6 条）  
- 下拉刷新不做（本地 DB 无强需求）  
- Toast 位置与 FAB/底栏避让再校准  

### 6.3 工程可改性（服务 UI）

| 任务 | 目的 |
|------|------|
| 拆 `Home` 为 `HomeHero` / `TodayQueue` / `OnThisDay` / `HomeLibrary` | 改首页不碰 1200 行巨文件 |
| `07-pages.css` 按域拆 `home/people/memories/detail` | 降冲突 |

## 8. 视觉方向细则（执行时遵守）

来自品牌与 Apple 材料原则的落地约束：

1. **少一层玻璃**：内容卡默认更实一点；只有顶栏/底栏/Sheet 用强 blur  
2. **主色克制**：渐变留给主按钮与 FAB，列表不要条条渐变  
3. **圆角阶梯**：页面 28 / 卡 18–20 / 控件 14–16 / pill 999  
4. **间距用 4 的倍数**：8 / 12 / 16 / 24，避免 11、13 散落  
5. **字阶**：展示 22–24，标题 17–18，正文 14–15，meta 12–13  
6. **中文 tracking**：大标题可略紧，正文不要负 tracking  
7. **图标**：统一 stroke 宽度；避免同屏 outline/filled 混用过多

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 首页改动激怒老用户 | 折叠状态继续持久化；统计移入「最近看看」可展开 |
| 缩略图性能 | 仅详细模式；限解码；复用 photo URL 生命周期 |

| CSS 巨石冲突 | 新样式进独立 `10-home.css` / 组件 css，少改 8k 行文件中段 |
| 与流体手感打架 | 新动效一律走 spring/reduced-motion 约定 |

## 12. 不建议做的「假优化」

- 再给首页加第 5 个数据可视化模块

- 为了「高级」上复杂自定义字体包（体积与中文渲染）  
- 无场景的 3D/粒子背景  
- 把设置项全部堆到首页
