# LifeLog 后续优化计划

目标：借鉴 FluxDO 的工程化、更新、反馈、性能和结构化能力，但只吸收适合 LifeLog 当前 Android 优先路线的部分。

## 阶段 1：更新中心增强

状态：已完成基础版

目标：
- 账号页能显示当前版本、最新版本、APK 名称、APK 大小、发布时间和检查时间。
- GitHub Release 内容能在应用内摘要展示。
- 用户发现新版本后可以直接打开 APK 下载入口或 Release 页面。

验收：
- `test:update-checker` 覆盖版本比较、Release 元数据解析和文件大小格式化。
- Android 端点击检查更新不会阻塞页面。

## 阶段 2：反馈诊断入口

状态：已完成基础版

目标：
- 账号页新增反馈入口。
- 一键复制诊断信息，包含版本、设备、屏幕、数据数量和备份健康状态。
- 诊断信息不包含具体人物姓名、地点名称、回忆标题或正文。

验收：
- `test:diagnostics` 确认诊断摘要生成正常且不泄露正文内容。
- GitHub Issue 入口可打开。

## 阶段 3：发版自动化

状态：已完成基础版

目标：
- 把版本号更新、CHANGELOG、README、releaseNotes、Android versionCode、APK 复制和 Release notes 生成串成脚本。
- 发版前自动检查当前版本是否有更新说明。
- 发版后输出 APK 大小、SHA256、包名、versionCode 和 Release 链接。

验收：
- 一个命令可以完成发布前检查。
- 手动漏改 README 或 releaseNotes 时脚本会失败。

## 阶段 4：图片性能优化

状态：已完成基础版

目标：
- 修复照片预览组件中用 `useState` 执行异步加载的问题，改为 `useEffect`。
- 对照片网格增加缩略图对象 URL 生命周期管理。
- 照片较多时提供“先显示前 N 张，展开全部”的轻量策略。

验收：
- 反复进入回忆详情不会持续增加未释放的图片 URL。
- 多图回忆页面首屏加载更快。

## 阶段 5：提醒体系增强

状态：已完成基础版

目标：
- 在提醒设置页显示未来 7 天提醒预览。
- 增加“长期未联系人物”建议。
- 增加“地点回访提醒”候选规则，但默认不强打扰。

验收：
- 提醒预览可解释每条提醒来自生日、纪念日、联系间隔或回忆回顾。
- 没有通知权限时仍能看到预览，但明确不会系统触发。

## 阶段 6：模块分层整理

状态：已完成基础版

目标：
- 将账号页、更新检查、反馈诊断、备份健康、提醒调度等能力按 feature/service 层逐步拆分。
- 降低页面组件直接处理复杂业务逻辑的比例。
- 保持小步迁移，不做大重构。

验收：
- 单个页面文件不继续膨胀。
- 工具函数有独立回归测试。

## 阶段 7：编辑器体验优化

状态：已完成基础版

目标：
- 快速回忆输入增加常用模板。
- 回忆正文支持轻量结构化段落提示。
- 标签、人物、地点建议更贴近已有数据。

验收：
- 新建回忆时填写成本下降。
- 快速回忆仍保持一屏内完成，不引入复杂富文本负担。
