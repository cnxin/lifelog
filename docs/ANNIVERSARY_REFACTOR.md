# LifeLog 日子：轻量化改造说明

## 产品范围

从人物、地点、回忆、安排组成的生活记录系统，收敛成直接管理日期的小工具。活动页面仅一页，编辑和数据管理使用对话框。不依赖旧全局 Context，不加载旧业务模块。

- 活动 `src`：166 个文件 → 12 个文件（包括样式和类型声明）。
- 运行时直接依赖：17 个 → 9 个。
- 移除 React Router、图片处理、二维码、UUID 以及无用 Capacitor 插件。
- 旧源码、旧脚本、旧原生分享代码移入 `react-app/legacy/`，不参与构建。
- 保留旧历史文件与 APK，因此以上不表示整个 Git 仓库大小减少。

## 数据隔离

| 内容 | 处理 |
| --- | --- |
| 新日子 | `LifeLogDays.days`，独立数据库 |
| 旧人物生日 / 周年纪念日 | 用户确认后复制，稳定 ID 去重 |
| 旧照片 / 地点 / 回忆 / 复杂安排 | 保留原库，不读写、不提供新版入口 |
| 新版 JSON | 严格验证全部记录，再用事务合并；已有 ID 不覆盖 |
| 旧版 JSON | 只提取人物生日和年度纪念日，报告无效旧记录数量 |

删除新版日子不影响旧库；手动再次迁移时可能重新导入。新版备份不包含旧库数据。升级前仍需备份完整旧版数据。

## 验证入口

- `npm test`：27 项测试（16 项领域规则与 11 项 Android 配置 / 缓存清理 / APK 验收检查），涵盖日期有效性、夏令时、跨年、闰年、公历/农历周年、农历闰月/大小月、排序、备份验证与旧格式提取。
- `npm run test:e2e`：浏览器创建、编辑、删除、持久化、筛选、搜索、导出、去重、焦点循环/恢复、旧库只读迁移、非法备份不写入、跨窗口刷新、320/375/390/768/1024/1440 宽度检查；同时运行 axe 的 WCAG A/AA 自动化规则扫描。
- `npm run build`：TypeScript 和 Vite 生产构建。
- `npm run test:offline`：生产构建首次访问预缓存完成后断网，验证重载、新增和再次重载后的持久化。
- `npx cap sync android`：更新 Web 资源和精简后的原生插件注册。

Web 的预缓存列表由构建时生成，包含所有 JS/CSS 分块；新 service worker 等旧窗口关闭再激活，不强制刷新未保存的表单。Android 不注册新 service worker，并注销旧版遗留的 `/sw.js`、清理本应用 Web 缓存（不碰数据库），避免旧缓存干扰 APK 更新；仍需真机冷启动验证。

## 尚需发布前真机验收

- 使用原签名覆盖升级，确认本机旧库可读、旧照片和回忆未损坏。
- Android 文件保存器的取消、成功、失败和文件再次导入。
- 返回键关闭编辑框，主页返回键最小化；状态栏、软键盘、不同字号和安全区域。
- 打包 / 签名 / 安装并检查移除的旧权限与系统提醒行为。
- 当前无系统通知、云同步、里程碑和内置更新能力；不是旧版功能等价升级。

发布范围限定为 `codex/anniversary-lite` 分支与独立 APK 的 GitHub 预发布版；不合并 `main`，不替换旧版 Release。

Android 测试版包名隔离、构建检查、原签名升级步骤与现有旧版回退标签，见 [Android 测试与升级验收](ANDROID_RELEASE.md)。
